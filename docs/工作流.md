# 工作流：从一句中文到一套 VASP 输入文件

> 这份文档回答三个问题：
> 1. 模型到底做什么、工具到底做什么（谁碰文件、谁不算数）；
> 2. 一条需求从输入到落盘，中间经过哪些步骤、卡在哪几道闸门；
> 3. 出错时应该看哪一层。

---

## 1. 一张图看懂四层结构

```
┌──────────────────────────────────────────────────────────────────────┐
│ 第 4 层  你（人）                                                    │
│   在网页/终端里写：源目录、输出目录、一句中文需求；看 diff 后点"写入" │
└───────────────┬──────────────────────────────────────────────────────┘
                │  中文需求（例："扩成 2x2x1，第 3 个原子换成 Co，ENCUT 520"）
                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 第 3 层  模型（可选）                                                │
│   Ollama / OpenAI 兼容端点，只做一件事：把中文翻成"操作清单" JSON    │
│   看不到 POSCAR 原文、看不到坐标、看不到路径；也不执行任何命令       │
└───────────────┬──────────────────────────────────────────────────────┘
                │  {"structure":{"ops":[{"op":"supercell",...},...]}, "incar":{...}}
                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 第 2 层  工具层（vasp_core.tools）                                   │
│   把"操作清单"变成"可执行动作"：读结构、读 INCAR、校验、写盘、出报告 │
│   每个工具都有参数 schema；写盘工具必须带 confirm=true               │
└───────────────┬──────────────────────────────────────────────────────┘
                │  调用函数（同进程内，不是 shell）
                ▼
┌──────────────────────────────────────────────────────────────────────┐
│ 第 1 层  脚本层（poscar / incar / kpoints / recipe / prep / report） │
│   真正干活的代码：解析文本、改晶格、重排元素、生成 diff、拒绝覆盖     │
│   只用 Python 标准库；pymatgen/ase 只在"切表面/加吸附质"时才用，可选  │
└───────────────┬──────────────────────────────────────────────────────┘
                ▼
        文件系统：输出目录（POSCAR / INCAR / KPOINTS / INCAR.diff /
                  change_report.md / recipe.json）
```

一句话：**模型只翻译，程序才动手；模型不在文件系统里，也不在计算里。**

## 2. 两条入口，同一套下层

| 入口 | 什么时候用 | 模型是否必需 |
|---|---|---|
| **规则模式**（`nl.py`） | 常见说法：扩胞、替换、空位、真空层、ENCUT、K 点、应变、批量换元素 | 不需要 |
| **模型模式**（`llm.py`） | 规则匹配不到，或一句话里混了多层意思 | 需要（本地 Ollama 即可） |

两种模式产出的东西完全一样：一份 **recipe（配方）**。后续所有步骤都不关心它是谁写的。

### 规则模式怎么工作

1. 用 12 条正则从上到下扫中文，命中就记一条操作；
2. **按操作在句子里出现的先后排序**（中文语序就是执行顺序）；
   例："扩成 2x2x1，第 3 个原子换成 Co" —— "第 3 个"指扩胞后的第 3 个；
3. 扫不掉的片段列成"没听懂"提醒人；
4. 碰到切表面、固定层、DFT+U、泛函、赝势选择、收敛测试 —— 直接标"需要人"。

### 模型模式怎么工作

1. 探测 `GET {base_url}/models`（默认 `http://127.0.0.1:11434/v1`，超时 3 秒）；
2. 在线 → 发 `SYSTEM_PROMPT + 一句摘要 + 你的原话`，要求只回 JSON；
3. 离线/超时 → 自动退回规则模式，日志里写明原因（不会假装成功）；
4. 模型回复用**括号配平**提取 JSON（不用正则，避免在第一个 `}` 处截断）；
5. 提取出的配方仍要过下面第 4 节的全部校验，**模型说对不算数，校验过才算数**。

发给模型的摘要长这样（strict 模式）：

```json
{"natoms": 1, "species": ["Cu"], "lattice_abc": [2.553, 2.553, 2.553],
 "has_incar": true, "has_kpoints": false, "incar_keys": ["ENCUT"]}
```

不含坐标、不含 POTCAR、不含任何路径。

## 3. 工具清单（模型能调用的只有这些）

| 工具 | 作用 | 会写文件吗 |
|---|---|---|
| `workspace_status` | 看源目录里有什么、结构多大、有没有 INCAR/KPOINTS | 否 |
| `read_structure` | 读 POSCAR，返回原子数/元素/体积/晶格（只读） | 否 |
| `read_incar` | 读 INCAR 的键值（只读） | 否 |
| `propose_recipe` | 把中文变成配方 JSON（模型/规则） | 否 |
| `validate_recipe` | 真跑一遍 dry-run，返回错误/警告/产物清单 | 否（临时目录里试算后删除） |
| `write_inputs` | 把配方写成新的算例目录（**必须 confirm=true**） | 是 |

> 早期版本还有 `verify_run`（读 OUTCAR 判收敛）和 `submit_hint`（给提交命令），
> 现在都移出主链路：本工具只负责"前处理"，算完怎么看结果由你自己决定。

## 4. 一次完整操作：把 Cu 扩成 2×2×1 并把第 3 个原子换成 Co

```
① 你输入
   源目录   D:\work\cu\            （里面有 POSCAR，可选 INCAR）
   输出目录 D:\work\runs\cu_co\
   需求     扩成 2x2x1，第 3 个原子换成 Co

② 程序读源目录（模型不读）
   POSCAR → Cu，1 个原子，a=b=c=2.5527 Å，V=11.76 Å³
   INCAR  → 有（ENCUT=400）；KPOINTS → 无

③ 理解需求
   规则模式：命中 supercell、substitute 两条
   模型模式：模型返回同样的两条 + 可能的 INCAR 建议；都要过校验

④ 试算（预览）
   在 .tmp_service/<job>/out 里真跑一遍 prep：
     扩胞 → 元素重排（Cu 4 个）→ 替换第 3 个 → Cu3Co1
     生成 POSCAR / INCAR / KPOINTS 候选
   用 difflib 生成 diff（只展示，不落盘到你的输出目录）

⑤ 五道闸门
   闸 1 配方 schema：未知字段/未知 op/缺参数 → 直接拒
   闸 2 操作合法：索引越界、元素符号非法、负体积 → 拒
   闸 3 INCAR 白名单：不在名单的键 → 拒；危险键（LDAU/NELECT/泛函）→ 拒
   闸 4 一致性：ISPIN=2 缺 MAGMOM、ISMEAR=-5 却 NSW>0、ENCUT 越界 → 拒或警告
   闸 5 写盘：输出目录已存在 → 拒（除非 --force）；源目录 → 永不写

⑥ 你看 diff，点"写入"
   写出 POSCAR / INCAR / INCAR.diff / change_report.md
   （POTCAR 不生成 —— 你在超算上按元素顺序拼）

⑦ 你拿走输出目录
   scp 到超算 → 与你的 POTCAR 放一起 → qsub vasp.sh
```

**全程没有一步在本机算能量。** `prep` 只做几何与文本；`ml_relax` 这类会调用 CHGNet 的操作
默认关闭，网页入口里根本不出现。

## 5. 人工必须确认的 6 个点

1. **源目录选对没有**（POSCAR 是你要改的那个，不是旧算例的）；
2. **元素顺序**：输出 POSCAR 的元素行 = 你拼 POTCAR 的顺序，中间不能变；
3. **INCAR 改动表**：每一行 `键 旧值 → 新值` 都看一眼，尤其是 ISMEAR、SIGMA、ISPIN、MAGMOM；
4. **危险键**：DFT+U、NELECT、泛函、vdW —— 工具**不会**自动写，需要你改模板；
5. **写盘目录**：必须是新目录；写错了源文件不受影响，但会多出一堆文件；
6. **KPOINTS**：如果源目录有，就原样复制；没有就按配方生成 —— 确认网格是否够。

## 6. 出错时看哪一层

| 现象 | 先去哪看 |
|---|---|
| 网页提示"模型离线，已用规则模式" | 第 3 层：`ollama serve`、`ollama list`、`curl 127.0.0.1:11434/v1/models` |
| "这句我拿不准/需要人确认" | 第 3 层规则：换更明确的说法，或开模型 |
| diff 里的结构不对 | 第 2 层：顺序问题（先扩胞还是先换原子）、索引是 1 基 |
| "缺少必需参数 miller" | 第 2 层：`surface` 要写 `miller`（如 `[1,1,1]`） |
| "structure.ops[i](...) 执行失败" | 第 1 层：具体操作的参数/边界，错误里带 op 名和下标 |
| "目标目录已存在" | 第 1 层闸 5：换个输出目录，或勾"允许覆盖" |
| 写出的 POSCAR 打不开 | 第 1 层：看 `change_report.md` 的"结构变化"表，对照源文件 |

## 7. 配置分层（改哪儿最省事）

优先级从高到低：

```
命令行参数  >  环境变量  >  vasp-prep.toml  >  代码默认值
```

| 想改什么 | 改哪里 |
|---|---|
| 模型地址/模型名 | `vasp-prep.toml` 的 `[llm] base_url / model`，或 `VASP_PREP_LLM_BASE` / `VASP_PREP_LLM_MODEL` |
| 端口 | `[ui] port`，或 `VASP_PREP_PORT` |
| 不自动开浏览器 | `[ui] auto_open=false`，或 `VASP_PREP_NO_BROWSER=1` |
| 关掉模型只用规则 | `[llm] enabled=false` |
| 默认源/输出目录 | `[paths] default_source / default_output` |
| 隐私档位 | `[llm] privacy = strict / normal / off` |

## 8. 边界（说清楚，免得误会）

**能做**：改晶格/扩胞/替换/删原子/加原子/真空层/固定层/应变/批量换元素/切表面/加吸附质
（后两项需 pymatgen、ase）；改 19 个常用 INCAR 键；生成 KPOINTS（四种模式）；出 diff 与报告。

**不做**：算能量、跑 VASP、判收敛（可另用 `vasp_core.verify`，但不在网页链路）、
拼 POTCAR 内容、上传/下载、自动提交作业、决定磁性/DFT+U 这类科学选择。

**判不了**：结果物理上对不对。工具只能保证"文件按你说的改了、格式合法、元素顺序一致"。
