## 1. 四层架构（一句话：入口很薄，服务层做组合，核心层只干活）

| 层 | 文件 | 只负责什么 | 谁调它 |
|---|---|---|---|
| **入口层** | `prep.py` `webui.py` `chat.py` `batch.py` `db.py` `__main__.py` | 收参数、开服务、打印结果 | 你（命令行/网页/双击 bat） |
| **服务层** | `service.py` `batch.py` `db.py` | 把"理解 → 执行 → 比对"串起来；批量/数据库的编排 | 入口层 |
| **核心层** | `poscar.py` `incar.py` `kpoints.py` `recipe.py` `report.py` | 结构运算、参数类型与白名单、按顺序执行 ops、生成 diff/报告 | 服务层 |
| **基础层** | `config.py` `paths.py` `errors.py` `llm.py` `nl.py` `browse.py` | 读配置、目录规则、异常、模型/规则、选文件夹 | 所有层 |

**一条铁律**：核心层不读网页请求、不打印、不联网。它只接收数据、返回数据。
所以测试可以只测核心层（163 项里的绝大多数），不用起服务。

## 2. 主流程：一次"预览"

```
 你的一句话（中文）
        │
        ▼
 ┌──────────────┐   在线   ┌──────────────┐
 │ nl.py 规则层 │ ───────► │ llm.py 模型层 │   ← 谁在线用谁；模型挂了退回规则
 └──────┬───────┘          └──────┬───────┘
        └──────────┬──────────────┘
                   ▼
            配方 JSON（recipe）
                   │  recipe.py 校验：字段名、类型、范围、未知键一律报错
                   ▼
        ┌──────────────────────┐
        │ 按 ops 顺序逐个执行   │  poscar.py：扩胞/替换/空位/加原子/应变/真空/固定…
        └──────────┬───────────┘  incar.py：只用白名单键，越界拒绝
                   │              kpoints.py：四种模式
                   ▼
            新结构 + 新 INCAR/KPOINTS
                   │  report.py：INCAR.diff / change_report.md / 审计
                   ▼
        service.stage_recipe()  写到 .tmp_service/<id>/（临时舞台）
                   │  只读比对：旧文件 vs 新文件
                   ▼
             网页显示摘要 + diff
                   │  你点「写入」
                   ▼
        service.write_job_obj()  →  runs/<名称>/（新目录，绝不覆盖源目录）
```

关键点：

- **默认不写盘**：`prep.py` 不加 `--write` 只试算；网页「预览」也只写临时舞台。
- **舞台隔离**：`.tmp_service/<id>/` 用完即删，失败也删；用户目录在"确认"之前不动。
- **写文件要二次确认**：`/api/write` 必须带 `confirm`，否则 400。

## 3. 代码级调用链（照着函数名读代码）

### 3.1 网页（最常用）

```
webui.py  Handler
├─ GET  /                 → 读 web/index.html（单页，无框架）
├─ GET  /api/status       → config.load() + llm.probe()
├─ GET  /api/browse       → browse.pick_directory()（弹系统选择框）
├─ GET  /api/open|ls      → 打开/列出 runs、batches、materials、imports
├─ POST /api/preview      → service.preview()
│     ├─ summarize_source()       读 POSCAR，报几原子、元素、体积
│     ├─ understand()             nl / llm → 日志 + 配方
│     ├─ compose_recipe()         补 calc 预设、套 INCAR 策略
│     └─ stage_recipe()           prep.run(dry) → summary + diffs
└─ POST /api/write        → service.write_job_obj() → prep.run(write)
```

### 3.2 命令行配方（适合脚本/复现）

```
prep.py  main()
├─ build_parser()              参数：配方路径、--write、--potcar-mode、--json
├─ recipe.load(path)           读 JSON → 校验 → Recipe 对象
├─ recipe.apply_ops(st, ops)   只碰结构，按 ops 顺序
├─ build_incar()               base INCAR + 预设 + 覆盖 → 变更表
├─ make_diff() / write_report()
└─ 写 POSCAR / INCAR / KPOINTS / change_report.md
```

### 3.3 批量（一个需求 × N 个材料 × M 个参数）

```
batch.py
├─ scan_materials(root)        只读：每个子目录里找 POSCAR
├─ plan_targets()              材料 × 参数 → 目标路径清单（先算名字，不建目录）
├─ compose_recipe()            只理解一次，所有材料共用同一份 ops
├─ for 每个目标：stage_recipe() 各自跑一遍，失败只标红这一项
└─ write_batch()               batches/<批次>/<材料>[/ivdw_<值>]/ + batch_summary.csv
```

### 3.4 数据库（检索 → 下载 → 导入）

```
db.py
├─ search(provider, formula)   mp/oqmd：OPTIMADE 免 key；aflow：给链接
│                              2dmatpedia：本地缓存整库再筛
├─ download(candidate)         → materials/<provider>_<id>/{POSCAR,SOURCE.json}
└─ import_file/import_folder()  本地 CIF/POSCAR/zip → materials/（CIF 需 pymatgen）
```

## 4. 目录长什么样（运行时自动创建）

```
vasp-prep\
├── runs\            单文件输出：runs\<名称>\
├── batches\         批量输出：batches\<批次>\<材料>\ivdw_<值>\
├── materials\       数据库下载 / 导入：materials\<provider>_<id>\
├── imports\         手动放文件的地方（可不用）
├── cache\           2Dmatpedia 等检索缓存
├── .tmp_service\    预览舞台（自动删）
├── vasp_core\       代码
├── web\index.html   网页（单文件）
├── tests\           163 项 unittest
└── docs\            本文件、网页使用、批量处理、数据库下载
```

## 5. 哪些是主路径，哪些是"留着但不启用"

| 类别 | 文件 | 状态 |
|---|---|---|
| 主路径 | `poscar incar kpoints recipe report service batch db nl llm config paths errors webui chat browse` | 每次都会用到 |
| 可选（默认不启用） | `backends\*`（pymatgen/ase 切面、吸附）、`ml.py`（CHGNet 预弛豫）、`verify.py`（读 OUTCAR 判收敛）、`cluster.py`（scp/qsub）、`ops_ext.py`、`potcar.py`（本地拼 POTCAR） | 不装依赖也能跑主流程 |
| 给智能体用 | `tools.py` `agent.py` `vasp_mcp\` `skill\vasp-prep\` | 不影响人用网页 |

判断方法：`grep -r "import ml\|import cluster\|import verify" vasp_core` —— 主路径里没有任何一行 import 它们。

## 6. 出错时先看哪一层（排错顺序）

| 现象 | 先看 | 具体位置 |
|---|---|---|
| 中文理解错（多做/少做） | 规则/模型层 | `nl.py` 的规则、`llm.py` 的系统提示；网页日志会写"理解结果" |
| 原子数/元素不对 | 核心层 | `poscar.py` 对应 `op_*`；配方里 ops 顺序 |
| INCAR 值不对/被拒 | 核心层 | `incar.py` 类型表、白名单、预设 |
| 文件没生成/生成一半 | 服务层 | `service.stage_recipe` 的异常、`prep.py` 的 `--write` |
| 网页报 400/500 | 入口层 | `webui.py` 对应路由；错误信息里有异常类型 |
| 路径/权限问题 | 基础层 | `paths.py`、`webui.runtime_mode()`、`docs\网页使用.md` 的受限模式一节 |

## 7. 为什么这样分层（三个真实约束）

1. **模型不可靠**：它只准输出 JSON，且键名/类型全量校验；理解错只影响"选哪些 op"，不会直接改文件。
2. **VASP 容易静默错**：POSCAR 的元素顺序、Selective 的 T/F、速度块格式，错了 VASP 不报错但结果全错。所以这些都放在核心层，并有单元测试锁住。
3. **你不想学编程**：入口必须薄且稳定——网页三个页签覆盖 95% 场景，命令行只是备用与复现。
