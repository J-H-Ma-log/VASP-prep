# 00 总表：一次点击到底跑了哪些行

这份文档回答两个问题：

1. **整个项目是怎么跑起来的**——从双击 `启动网页.bat` 到页面上出现 diff；
2. **每个阶段具体落在哪个文件、哪一行**——后面每一份文档按"行号"展开细节。

> 行号以本次提交（v4 之后的逐行文档版）为准。改代码后行号会漂，**用函数名搜，不要死记行号**。
> 本文所有"执行次数"来自一次真实运行：规则模式、源目录 `C:\Users\28476\Desktop\test\MoS2`、
> 需求"扩成 2x2x1，第 3 个原子换成 Co"，先预览再写入。

## 0. 先看结论：一次点击的 9 个阶段

| # | 阶段 | 谁触发 | 关键代码（文件:行） | 产出/结果 | 出错会怎样 |
|---|---|---|---|---|---|
| 1 | 启动服务 | 双击 `启动网页.bat` | `vasp_core\__main__.py:32` → `webui.py:438 main()` | 监听 `127.0.0.1:8765`，自动开浏览器 | 端口占用 → 顺延到 8766~8770；全占用 → 报错退出 |
| 2 | 收请求 | 点"预览" | `webui.py:350 do_POST()` → `/api/preview` 分支 | 解析 JSON，校验 `source/text` | 缺字段 → 400 + 中文原因 |
| 3 | 读源目录 | `service.preview` 内部 | `service.py:383 preview()` → `:96 summarize_source()` → `poscar.py:425 read_poscar()` | `summary` dict（原子数/元素/体积/INCAR 键） | 目录不存在/没 POSCAR → `PrepError`，网页红条 |
| 4 | 理解中文 | 同上 | `service.py:308 compose_recipe()` → `:160 understand()` | `recipe` dict（ops + incar.overrides + calc） | 模型超时/胡说 → 自动退回规则模式，时间线写明 |
| 5 | 补全配方 | 同上 | `service.py:203 _finalize_recipe()`、`:241 _apply_calc_policy()` | 补 `base_dir`/`version`，决定套不套 INCAR 预设 | 纯结构编辑不套预设，避免 INCAR 被整篇重写 |
| 6 | 临时试算 | 同上 | `service.py:341 stage_recipe()` → `prep.py:156 run()` | `.tmp_service/<id>/out/` 里真实的 POSCAR/INCAR/KPOINTS | 任何 `PrepError` → 删舞台、原样抛给网页 |
| 7 | 生成 diff | 同上 | `service.py:278 _diff_text()`（`stage_recipe` 内调用） | `diffs {POSCAR: ..., INCAR: ...}` | 无变化则 diff 为空，页面不显示该页签 |
| 8 | 等你点写入 | 点"写入" | `webui.py` `/api/write` → `service.py:537 write()` → `:502 write_job_obj()` | 先 `_preflight_out` 试写，再重跑 `prep.run` 到 `runs\<名字>\` | 目录不可写 → 给出三条具体建议（换目录/加白名单/换启动方式） |
| 9 | 收尾 | 写入成功/关闭服务 | `service.py:533 shutil.rmtree(stage)`、`:550 cleanup_all()` | 舞台删除，输出目录留 4~5 个文件 | 清理失败只影响临时目录，不影响算例 |

一句话记忆：**前 7 步都在 `.tmp_service` 里做，第 8 步才碰 `runs\`；源目录全程只读。**

## 2. 调用树（缩进表示"谁调谁"）


## 3. 数据在每一步长什么样

| 步骤 | 数据形态 | 存在哪里 | 谁产生 | 谁消费 |
|---|---|---|---|---|
| 1 | 文本行 | 源目录 `POSCAR`/`INCAR`/`KPOINTS` | 用户 | `read_poscar` / `parse_incar` |
| 2 | `Structure` 对象 | 内存 | `poscar.py:249` | 所有 `op_*`、`write_poscar_text` |
| 3 | `summary` dict | 内存 + 网页 | `service.py:96` | 时间线、模型提示、批量扫描 |
| 4 | `recipe` dict（JSON） | 内存 → `stage/recipe.json` | `service.py:308` | `prep.run` |
| 5 | `summary2` dict | 内存 → HTTP JSON | `prep.py:296` | 网页摘要表、`write` 复用 |
| 6 | diff 文本 | 内存 | `service.py:278` | 网页 diff 页签 |
| 7 | 文件 | `.tmp_service/<id>/out/` | `prep.py:327-354` | 预览读取；写入后删 |
| 8 | 文件 | `runs\<名字>\` | `write_job_obj` 重跑 | 用户拷到超算 |

`recipe.json` 是唯一"跨阶段契约"：预览写它、写入重跑也读它，所以**你看到的 diff 与最终落盘一定同源**。

## 6. 读代码的顺序建议（按这份文档走一遍）

1. **先跑一次**：`python -m vasp_core webui`，用 MoS2 目录点"预览"，对照本文第 1 节的 38 行轨迹；
2. **读入口**：`__main__.py`（43 行）→ `webui.py:241 do_GET` / `:350 do_POST`（只读路由表，不读每个分支）；
3. **读主链**：`service.py:383 preview` 从头到尾读一遍，遇到不认识的函数再跳转；
4. **读结构**：`poscar.py` 的 `Structure` 类（第 124-242 行）→ `read_poscar_text`（249-414）→ 你关心的那个 `op_*`；
5. **读校验**：`recipe.py:181 load_recipe` → `incar.py:442 check_consistency` → `kpoints.py:169 check_kpoints`；
6. **读写盘**：`prep.py:326-373` 与 `report.py:63 make_change_report`。

每一步都可以在真实运行的时间线里找到对应行，看到"这一行执行了几次、当时在干什么"。
