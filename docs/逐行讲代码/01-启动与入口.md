# 01 启动与入口逐行讲解

对应文件：

- `vasp_core\__main__.py`（69 行）—— 统一入口 `python -m vasp_core <子命令>`
- `start_webui.bat`（28 行）、`启动网页.bat`（7 行）—— 双击启动
- `webui_launcher.py`（29 行）—— 嵌入式 Python 的 `sys.path` 垫片
- `vasp_core\webui.py`（484 行）—— 网页服务：路由、目录选择、受限环境判断
- `vasp_core\chat.py`（127 行）—— 终端版
- `vasp_core\prep.py` 的 `main`（440-480）与 `_print_human`（483-508）—— 命令行版

> 三种入口最后都落到同一层：`service.preview` / `service.write`（网页、终端）或 `prep.run`（命令行、批量的内核）。

# 一、启动路径总图

```text
① 双击 启动网页.bat
     └─ call start_webui.bat
          ├─ chcp 65001（控制台 UTF-8）
          ├─ 找 ..\chgnet_env\python\python.exe（没有就退回 PATH 里的 python）
          └─ 运行 webui_launcher.py
               └─ sys.path.insert(0, 项目根)，然后 from vasp_core.webui import main

② 命令行 python -m vasp_core webui
     └─ __main__.main(["webui"]) → COMMANDS["webui"] → webui.main([])

③ 命令行 python -m vasp_core chat
     └─ __main__ → chat.main([])

④ 命令行 python -m vasp_core prep recipe.json --write
     └─ __main__ → prep.main([...]) → prep.run(args)
```

**为什么要有 `webui_launcher.py`**：项目自带的 `chgnet_env` 是 Windows 嵌入式 Python，
`._pth` 把 `sys.path` 钉死了，既不认当前目录也不认 `PYTHONPATH`，`-m vasp_core.webui`
会直接 `ModuleNotFoundError`。而"运行一个 .py 文件"时 Python 会把该文件所在目录放进
`sys.path[0]`——所以用一个 29 行的脚本把项目根塞进去就能跑。

# 三、双击启动：`启动网页.bat` 与 `start_webui.bat`

## 3.1 `启动网页.bat`（7 行）

| 行 | 代码 | 说明 |
|---|---|---|
| 1 | `@echo off` | 不回显命令 |
| 2-6 | `REM ...` | 说明：真正的逻辑在 `start_webui.bat`（ASCII 名，桌面快捷方式指向它）；本文件只转发 |
| 7 | `call "%~dp0start_webui.bat"` | `%~dp0` = 本文件所在目录，带反斜杠结尾 |

# 七、入口层最容易踩的三个点

1. **`-m` 与嵌入式 Python**：`chgnet_env` 下必须走 `webui_launcher.py`（或 `chat_launcher.py`），不能直接 `-m vasp_core.webui`。
2. **端口**：`8765` 被占会顺延到 `8766…8770`；控制台第一行会打印真实地址，别死记 8765。
3. **运行模式**：从 AI 工具里启动常常是 `Low` 完整性 → 写不了桌面；控制台会直接提示"从资源管理器双击 bat"。这不是程序 bug。
