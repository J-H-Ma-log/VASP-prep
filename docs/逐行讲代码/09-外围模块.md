## 0. 哪些在主链路、哪些是可选

主链路指 `webui.py → service.py → prep.py → recipe.py → poscar.py`（见 05 那份文档）。下面这些模块里，只有 `config.py`、`paths.py`、`errors.py` 会被主链路直接 import；`llm.py`/`browse.py` 由 `webui.py`/`service.py` 间接用到；`ml.py`、`verify.py`、`cluster.py`、`backends\*`、`ops_ext.py` 都属于"不装依赖也能跑主流程"的可选能力。

### 1.1 逐行讲解

**干什么**：只做转发。`COMMANDS` 里的 5 个子命令各自保留自己的 `main`，行为、帮助、退出码都不改；本文件不写任何业务逻辑。
**参数**：`argv: list[str] | None = None`。`None` 表示读 `sys.argv[1:]`；传列表时（测试/程序内调用）优先用列表。
**返回**：`int` 退出码。没参数打印用法后返回 **2**；`-h/--help/help` 返回 **0**；不认识的子命令返回 **2**；正常子命令返回它自己的 `main()` 返回值。
**异常**：本函数自己没有 `try/except`——子命令抛什么就冒泡什么（`prep.main` 之类在各自模块里已经把 `PrepError` 转成退出码）。

| 行 | 代码（原文） | 说明 |
|---|---|---|
| 1-14 | `"""统一入口： ... """`（整段 docstring） | 模块 docstring：解释"以前有五个入口，新手要先记住模块名"的痛点，以及 4 条常用命令示例；注意 docstring 里写了 `python -m vasp_core <子命令>` 的用法 |

补充两点（读代码时容易踩）：

- 直接 `python vasp_core\__main__.py` 会失败：文件里用的是相对导入 `from . import ...`，没有父包时 Python 会报 `ImportError: attempted relative import with no known parent package`（未实测，属于 Python 相对导入的既有行为）。要跑就用 `python -m vasp_core`。
- 因为第 19 行是**一次性全部导入**，任何一个子命令模块的 import 期错误（例如 TOML 语法错导致 `webui.py:52` 抛异常）都会让所有子命令一起起不来。

### 9.2 `agent.py`（406 行）—— OpenAI 兼容接口的 tool-calling 智能体

### 9.10.3 `serve`（166-199）

| 174-177 | `for raw_line in stdin:` / `line = raw_line.strip()` / `if not line: continue` | 跳过空行 |

## 10. 可选模块怎么关掉 / 怎么打开

先记一条总原则：**这些模块都是"用到才 import"**。主链路的 `webui.py → service.py → prep.py → recipe.py → poscar.py` 没有 import `ml.py`、`verify.py`、`cluster.py`、`backends\*`、`ops_ext.py`、`tools.py`、`agent.py`、`vasp_mcp\*`（`grep` 验证：这些名字只出现在各自的调用点，`prep.py` 里是函数内/参数分支才 import）。所以"关掉"通常不是改配置，而是**不传参数、不装包、不启动对应入口**。

### 10.1 一张表：开关在哪

| 能力 | 默认状态 | 怎么打开 | 怎么关掉 | 依赖 |
|---|---|---|---|---|
| 模型理解中文（`llm.py`） | `[llm] enabled=true`、`privacy="strict"`，但**模型服务不一定在** | 启动 Ollama（或任何 OpenAI 兼容端点），改 `base_url`/`model`；`python -m vasp_core.chat` 会先探活 | `vasp-prep.toml` 里 `enabled = false` **或** `privacy = "off"`；也可不启动模型服务（探活 3 秒失败自动退规则） | 无第三方包（标准库 urllib）；需要 HTTP 端点 |
| 网页"选择…"弹框（`browse.py`） | 总是启用 | 网页点"选择…" | 无配置开关；用户直接手输路径即可绕过 | Windows：PowerShell + 桌面会话；Linux：zenity/kdialog；macOS：osascript |

### 10.4 读代码时值得记住的 6 个"现状与注释不一致"

这些不是让你改代码，而是避免被注释误导（每一条都在前面标了出处）：

1. `config._load_toml` 的 docstring 说"语法错误由 `load()` 转成提示"，但 `load()` 没有对应捕获（2.2）。
2. `paths.resolve_kind` 的 docstring 说"未知 kind 由 webui 转成 400"，实际 `KeyError` 会落到 webui 的 500 兜底（3.5）。
3. `llm.ProbeResult.has_model` 是占位属性，永远返回 False，也没有 `probe_for()`；全仓库没有调用点（9.1.1）。
4. `prep.py` 定义了 `--verify`/`--no-strict-ionic`/`--kpath` 三个参数，但 `run()` 里没有读取它们的代码；`verify_run`/`render_verify_report`/`magmom_file_text`/`kpoints_line_text` 在 prep 里只有 import 没有调用（9.4/9.7/9.3）。
5. `ml.py` docstring 说磁矩结果会写进 `MAGMOM.chgnet` 文件，但 `prep.run()` 里算出的 `magmom` 字典没有被使用、`magmom_file_text` 也没有调用点（9.3.5）。
6. `prep.py` 定义了 `--doctor`（build_parser 第 137-138 行），`backends.describe` 也被 import（第 35 行，别名 `backend_describe`），但 `main`/`run` 里没有使用它们——`--doctor` 当前不会输出任何自检信息（10.3 第 2 条给了替代命令）。

> 结尾一句：外围模块的价值不在"功能多"，而在**依赖边界清楚**——核心（`poscar/incar/kpoints/recipe/prep`）永远能跑；可选能力要么在调用点给出能照做的安装提示，要么在不可用时自动降级（模型→规则、vasprun→OUTCAR、桌面弹框→手输路径、确认缺失→拒绝写盘）。
