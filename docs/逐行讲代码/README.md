# 逐行讲代码 · 索引

这份文档集回答一个问题：**这个程序从启动到写出算例，每一行到底在干什么。**

不是"大概讲原理"，而是每个文件一张函数总览表，每个函数一段"干什么 / 参数 / 返回 / 异常"，然后一张 `| 行 | 代码原文 | 说明 |` 的逐行表——行号就是源文件的真实行号，代码就是源码去掉行首缩进后的原文。

- 覆盖：`vasp_core\` 全部模块 + `web\index.html` + 两个 launcher
- 规模：10 份文档、约 9,600 行、约 735 KB
- 每份文档开头都有一张 **ASCII 逻辑树**：先看"谁调用谁"，再往下读逐行表
- 基准：`v4.0.0`（tag `v4.0.0`），写于 2026-11-12，写作期间源码零改动

## 3. 建议阅读顺序

第一次读，按这个顺序走，每步 5–15 分钟：

1. **00**：先看"38 行真实轨迹"那张表——对程序跑起来的样子有画面。
2. **01**：弄明白你是从哪个门进来的（网页 / 终端 / 命令行）。
3. **02**：中文 → 配方 JSON，这是"翻译层"。
4. **03**：结构操作，这是"施工层"，也是项目里最容易出错的一层。
5. **05**：预览和写入两条路，明白为什么要点两次。
6. **04**：INCAR/KPOINTS 的规则，按需查。
7. **06 / 07 / 08 / 09**：用到哪块查哪块。

只想知道"整件事怎么跑"的人，读完 00 + 05 就够了。

## 4. 怎么按行号核对

每张表的三列是 `行 | 代码原文 | 说明`：

- **行**：源文件真实行号（1 起）。连续多行注释、多行 docstring、跨行表达式会合并成一条，写成 `起–止`。
- **代码**：源码去掉行首缩进后的原文；表格里的 `\|` 是 Markdown 转义，源码本身是 `|`。
- **说明**：这一行"为什么在这里"、条件是什么、调用了谁。

核对方法：

- VS Code / PyCharm：`Ctrl+G` 输入行号直接跳；找不到入口函数时先看该文件第 1 节的"文件结构总览"。
- 想确认某行没抄错：复制"代码"列，在当前文件里 `Ctrl+F`（去掉缩进后应该能搜到）。
- 想知道"这个函数被谁调用"：看总览表的"被谁调用"列，或文档里每节的"谁调用我"。

## 6. 文档约定（避免误会）

- "异常"只指函数**主动 `raise`** 的；参数形状不对导致的 `IndexError` 只在值得注意时提一句。
- "未发现调用"是写文档时全仓 grep 的结果，不代表它永远不会被外部脚本调用（`__init__.py` 导出的函数尤其如此）。
- 源码与注释冲突时，**以源码为准**，并在文档里标注"注释写的是 X，实际是 Y"。
- 没实跑验证的行为，会写"按代码推断"，不写成结论。
